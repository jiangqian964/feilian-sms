> 本手册面向负责日常配置与运维的业务运维人员，逐项说明 WebUI 管理台四个视图的操作方法。界面为原生网页（`go:embed` 内嵌，零外部依赖），实现源码见 [web/static](../web/static)；部署与访问地址见 [05 · 环境部署说明文档](./05-环境部署说明文档.md)。

## 1. 登录与通用说明

### 1.1 访问入口

- 在 PC 浏览器打开：`http://<网关主机IP>:8080/`（端口以部署时 `server.listen` 为准，默认建议 8080）。
- **无登录页/无账号体系**：管理台不设应用层登录，访问控制依赖网络边界。部署时通过 `server.admin_cidrs` 限定来源网段（只判定直连 IP，不信任代理转发头），请仅在受信内网或经管控的跳板环境打开。
- 推荐使用当前版本 Chrome / Edge / Firefox；页面为响应式宽屏布局，设计目标为 PC 端内网操作。

### 1.2 界面结构

- 顶部：系统标题、四个页签（**系统设置 / 通道 / 场景绑定 / 发送记录**）、右侧健康角标。
- 健康角标每 20 秒静默探测一次 `/api/health`，文案为 `服务正常`（绿）/ `异常 <HTTP码>` / `无法连接` / `检查超时`（红）；异常时请按部署文档排查服务状态。
- 页签切换时：首次进入懒加载数据；再次进入自动刷新当前视图。
- 数据加载中显示骨架屏；操作结果以右上角轻提示（成功/失败/警告）反馈；字段级校验错误直接显示在对应输入项下方，通道保存被整体拒绝时详情区顶部出现红色横幅并指明字段名。
- 破坏性操作（删除通道）弹出二次确认框，可点「取消」、按 Esc 或点遮罩关闭。
- 页面具备键盘可达性与 ARIA 标签，记录行可用 Tab 定位后回车打开详情。

### 1.3 首次上线操作路线图

```
① 系统设置   填 Verification Token、Webhook 路径、对外访问基址、运行阈值 → 保存（热生效）
② 通道       从「HTTP JSON 示例预置」建通道 → 补 appCode/appSecret/orgCode/templateCode 等常量 → 保存
③ 场景绑定   为需要的场景选择通道、模板码、参数下标 → 打开启用胶囊 → 保存
④ 验证       通道详情页「测试发送」→ 飞连后台保存订阅完成 challenge → 发真实验证码 → 发送记录核对
```

## 2. 系统设置视图

路径：顶部页签「系统设置」。全部项目保存后**立即热生效，无需重启服务**。

### 2.1 接入校验

| 项目 | 必填 | 说明 |
|---|---|---|
| Verification Token | 是 | 与飞连事件订阅中的 Verification Token 完全一致，用于校验请求来源；普通接入参数，明文保存（非密钥） |
| Encrypt Key（事件加密，本期可不启用） | 否 | 密码框，**留空表示不修改**；未设置时显示徽标「未设置（本期默认不启用事件加密）」，已设置显示「已设置：掩码」 |
| 「清空已保存的 Encrypt Key」勾选框 | 否 | 与输入新值互斥（输入新值时勾选框自动禁用，反之亦然）；当前未设置 Key 时勾选框禁用 |

> 安全提示：一旦配置了 Encrypt Key，服务端将强制按 AES-256-CBC 密文信封解析飞连事件（防降级）；飞连侧必须同步开启加密，否则事件无法解析。本期默认明文信封，保持留空即可。

### 2.2 厂商回执鉴权（可选）

| 项目 | 必填 | 说明 |
|---|---|---|
| 厂商回执鉴权 Token | 否 | 密码框，**留空表示不修改**；长度至少 16 个字符且不能含空白；未设置时回执端点不校验（依赖内网/网络层隔离），已设置显示「已设置：掩码」 |
| 「清空已保存的回执鉴权 Token」勾选框 | 否 | 与输入新值互斥；当前未设置时勾选框禁用；勾选保存后回执端点恢复为不校验 |

启用后，厂商（或反代/回调网关）调用回执地址时必须以下列任一方式携带同一 Token，否则一律返回 401：

- 请求头 `X-Receipt-Token: <Token>`（推荐，不入访问日志的 URL）；
- 或查询参数 `?token=<Token>`（仅当厂商无法自定义请求头时使用）。

> 注意：Token 热生效，启用/更换后须立即同步通知厂商侧更新；启用期间缺失或错误 Token 的回执会被拒绝并写入 Warn 日志（含来源直连 IP），短信主发送状态不受影响。

### 2.3 事件订阅地址

| 项目 | 必填 | 说明 |
|---|---|---|
| Webhook 接收路径 | 是 | 必须以 `/` 开头、不含空白与 `?`/`#`，且不得占用 `/api`、`/receipts`、`/health` 保留前缀；默认 `/feilian/sms/events`；**保存后旧路径立即失效**，飞连后台需同步更新 |
| 对外访问基址 | 否 | 形如 `http://网关IP:8080` 或经反代的 `https://短信网关.公司域名`，用于拼接完整地址；留空仅展示相对路径 |
| 完整事件订阅 URL（只读） | — | 自动拼出 `基址 + Webhook 路径`，点「复制」拷贝，填到飞连事件订阅的请求地址中 |
| 厂商回执地址示例（只读） | — | 形如 `基址/receipts/{通道ID}`，点「复制」后把 `{通道ID}` 替换为示例厂商通道的真实 ID，申请示例厂商凭证时填报；启用 2.2 的 Token 后，还需把 Token 以 `X-Receipt-Token` 头（或 `?token=`）告知厂商侧 |

### 2.4 运行阈值

| 项目 | 范围 | 默认 | 说明 |
|---|---|---|---|
| 单次下发超时（毫秒） | 100 ~ 60000 | 2000 | 单次转发示例厂商的超时；飞连要求 3 秒内返回 200，建议 ≤2000 |
| 在途补发阈值（毫秒） | 1000 ~ 86400000 | 120000 | pending 记录超过该时长未获终态响应，即被后台补发 worker 扫描续发；服务每 30 秒扫描一批（≤100 条），每条最多自动续发 3 次，仍未成功则置为「补发次数耗尽」终态 |

页面底部显示「上次更新」时间。点击「保存设置」后成功提示「系统设置已保存并热生效」；若某项非法，输入框下方与轻提示同时给出字段化错误（如超时超范围），不会落库。

## 3. 通道视图

路径：顶部页签「通道」。采用**左侧通道列表 + 右侧详情**双栏布局。列表项显示通道名称、启用徽标（已启用/已停用）与签名策略（不签名 / 示例厂商 SHA-1 加盐 / HMAC-SHA256）。

### 3.1 新建通道

点击右上角「＋ 新建通道」，在弹窗中选择创建方式：

| 方式 | 说明 |
|---|---|
| **HTTP JSON 示例预置**（默认，推荐） | 已内置 `${base}/sms/send` 的 9 行字段映射与 SHA-1 加盐签名，创建后只需补填基址、常量与密钥 |
| **空白 HTTP 通道** | 从零配置；需额外填写「基址 Base URL」与「请求路径 URL」，适合对接其他厂商 |

填写「通道名称」（必填，如「示例短信平台-生产」）与「描述」（可选），点「创建」。成功后自动选中新通道，提示「通道已创建，请补全凭证与模板参数」。

> 示例厂商预置的基址默认 `https://sms.example.com:1443`、路径 `${base}/sms/send`，真实上线前在出站请求区核对。

### 3.2 通道详情表单（8 个分区）

#### 分区 1 · 基本信息
通道名称（必填）、描述。

#### 分区 2 · 出站请求

| 字段 | 说明 |
|---|---|
| 基址 Base URL | 如 `https://sms.example.com:1443`，可留空而在 URL 写全地址 |
| 请求路径 URL（必填） | 支持 `${base}` 占位，如 `${base}/sms/send`，也可写完整 URL |
| HTTP 方法 | 下拉：POST（默认）/ GET / PUT，服务端强制白名单校验 |
| Content-Type | 默认 `application/json` |
| 额外请求头 | 键值对编辑器（增删行）；值中支持 `${const:name}` 与 `${constb64:name}`（Base64）插值常量 |

#### 分区 3 · 通道常量
逐行维护「常量名 + 值 + 是否密钥」：

- 非密钥常量（如 `appCode`、`orgCode`）随配置明文保存；
- **勾选「密钥」的常量（如 `appSecret`）真实值仅以 AES-256-GCM 密文存储**，再次打开只显示掩码占位，密钥输入框**留空表示不修改原值**；
- 示例通道至少需要：`appCode`、`appSecret`（密钥），如厂商要求组织编码再补 `orgCode`；模板码在场景绑定中按场景维护。

#### 分区 4 · 请求体字段映射表（核心）
**禁止手写 JSON 模板**，逐行声明「源 → 目标 JSON 路径」：

| 列 | 取值 |
|---|---|
| 目标路径 | 点分路径，如 `timestamp`、`data.mobile`；纯数字段表示数组下标（如 `params.0`） |
| 来源类型 | 内置变量 `variable` / 通道常量 `const` / 字面值 `literal` |
| 来源 | 变量下拉、常量名（带自动补全）或直接输入的字面值 |
| 值类型 | 字符串 `string` / 数字 `number` / 布尔 `boolean` / 原始 JSON `raw`（嵌入合法 JSON 片段） |

可用内置变量：`appSmsId`（我方唯一 ID）、`mobile`（归一化手机号）、`mobileNumber`（不含国家码）、`countryCode`（含 + 的国家码）、`smsType`、`templateCode`、`nonce`（5–6 位随机数）、`timestamp`（毫秒）、`params`（参数数组 JSON）、`param0/param1/param2…`（第 N 个模板参数，0 基）、`sign`（已生成的签名，仅供映射使用）。

每行可上移/下移（映射顺序即数组参数顺序）、删除；底部「＋ 新增映射」。示例厂商预置已给出全部 9 行映射（appCode/appSmsId/mobile/nonce/orgCode/params/sign/templateCode/timestamp），通常无需改动。

#### 分区 5 · 签名构造器

| 字段 | 说明 |
|---|---|
| 签名策略 | 不签名 `none` / 示例厂商 SHA-1 加盐 `sha1_salt` / HMAC-SHA256 `hmac_sha256` |
| HMAC 编码 | hex（小写）/ base64（主要服务 HMAC 策略） |
| 签名密钥常量 | 从「通道常量」中勾选为密钥的常量名（示例厂商选择 `appSecret`），输入框聚焦有自动补全 |
| 签名片段 | 按顺序拼接：每行选「字面量」（如 `timestamp=`、`&nonce=`、`&signData=`）或「变量」（timestamp/nonce/appSmsId 等）；可上下移动、删除、「＋ 新增片段」 |

示例预置的片段顺序固定为 `timestamp= + timestamp变量 → &nonce= + nonce变量 → &signData= + appSmsId变量`，与内置预置保持一致，请勿调整。

#### 分区 6 · 响应判定
解析示例厂商同步响应 JSON：

| 字段 | 示例厂商预置值 | 说明 |
|---|---|---|
| 成功标志路径 | `status` | 点分路径 |
| 成功期望值 | `0` | 宽松比较（数字 0 与字符串 "0" 等价）即判成功 |
| 厂商消息 ID 路径 | `data.id` | 用于回写厂商消息 ID |
| 错误描述路径 | `message` | 失败时记录厂商描述 |

#### 分区 7 · 手机号归一化
策略下拉：

- `cc_prefix`（默认，示例厂商：86 + 手机号）；
- `strip_plus`（去掉开头的 +）；
- `raw`（原样使用，含 +）。

#### 分区 8 · 厂商异步回执映射

| 字段 | 示例厂商预置值 |
|---|---|
| 厂商短信 ID 字段 | `smsId` |
| 我方 appSmsId 字段 | `appSmsId` |
| 回执状态字段 | `status` |
| 送达成功值 | `DELIVRD` |
| 送达失败值 | `UNDELIV`（预置自带；留空表示不识别失败态；其他状态值视为排队中/发送中等中间态，不改送达状态，仅推进序号） |
| 回执描述字段 | `statusMessage` |
| 回执序号字段 | `seqNo` |
| 成功响应原文 | 留空即默认精确返回 `{"status":0,"message":"success"}`（示例厂商要求逐字节一致，一般无需改） |

### 3.3 保存与校验

- 点「保存修改」：前端先做必填检查（通道名称、URL、映射行目标/来源不得为空、签名片段内容不得为空），随后**服务端用样例输入对整份配置做一次完整试渲染**（映射组装→签名→报文生成），任何错误都会以 400 拒绝并在详情区红色横幅指明字段与原因（如路径非法、常量未定义、密钥常量不存在）。
- 提示语「保存前将用样例输入完整试渲染；未填写密钥的脚手架允许保存」：首次从预置创建时尚未填 `appSecret` 也能先保存，补录密钥后再保存一次即可。
- 保存成功提示「通道配置已保存」，配置经快照热生效，不影响其他通道。

### 3.4 启用 / 停用 / 删除 / 复制回执地址

- 详情头部右侧「启用」/「停用」按钮即时切换；停用后该通道上的事件归类为「通道已停用」，只留痕不转发。
- 「删除」需在二次确认框中点「确认删除」：提示「删除后该通道的场景绑定将失效，历史发送记录保留。此操作不可撤销」。
- 头部只读展示该通道的**回执地址**（`基址/receipts/<通道ID>`）与「复制回执地址」按钮；未配置对外基址时提示先到系统设置配置。

### 3.5 测试发送（真发短信，会产生费用）

详情底部「测试发送」卡片（黄色警示：**将产生真实短信与费用，请仅使用测试手机号**）：

1. 选择短信场景（默认 `code`）；
2. 填模板码（必填，如 `SMS_TEST`）、国家码（默认 `+86`）、手机号（必填，**不含国家码**）；
3. 模板参数每行一个（如验证码与有效期两行）；
4. 点「发送测试短信」。

结果区展示：结果徽标「厂商受理成功 / 结果不确定，已转补发队列（warn 色）/ 厂商返回失败」、HTTP 状态码、`appSmsId`（形如 `test-<毫秒时间>-<6位hex>`）、厂商消息 ID、错误分类中文、描述。出现「结果不确定」表示请求已发出但未拿到明确响应（超时/连接失败/限流/服务端 5xx），记录保持 pending，由后台补发 worker 自动续发（最多 3 次），稍后可在发送记录查看最终结果。通道停用时返回 409 并提示。该次发送同样写入发送记录，来源标记为「测试发送」（`source=test`）。

## 4. 场景绑定视图

路径：顶部页签「场景绑定」。决定每种飞连短信场景走哪个通道、用哪个示例厂商模板码。若尚未建立任何通道，页面提示先到「通道」视图创建。

### 4.1 九种场景

| sms_type（接口值） | 界面名称 |
|---|---|
| `code` | 登录验证码 |
| `init_password` | 初始密码 |
| `reset_password` | 重置密码 |
| `alert` | 安全告警 |
| `guest_wifi` | 访客 Wi-Fi |
| `password_expiration` | 密码过期提醒 |
| `accout_expire` | 账号到期提醒 |
| `wifi_info` | Wi-Fi 信息通知 |
| `exchange_mfa` | Exchange 多因素认证 |

> `accout_expire` 为飞连官方枚举拼写，界面与接口均沿用，勿自行改写。

### 4.2 逐行配置

每行包含：

| 列 | 操作 |
|---|---|
| 启用 | 胶囊开关；**停用某场景请关闭胶囊而不是清空通道**（关闭后事件只留痕不转发） |
| 下发通道 | 下拉选择已建通道，或「— 未绑定 —」 |
| 模板码 templateCode | 示例厂商审核通过的模板码，如 `SMS_0001`；选了通道就必须填写 |
| 参数下标 | 飞连 params 数组的 **0 基**重排序列，英文逗号分隔（也容忍中文逗号/空格），如 `1,0` 表示交换第 1、2 个参数；**留空表示按原顺序透传** |

### 4.3 保存语义

- 点「保存绑定」执行**整表 UPSERT**：未改动/未选通道的场景保持服务端原样；已选通道的行随表提交。
- 前端校验：选了通道但模板码为空会阻止保存；参数下标必须为非负整数。
- 成功提示「场景绑定已保存（N 条）」，绑定热生效。

## 5. 发送记录视图

路径：顶部页签「发送记录」。所有短信（飞连事件与测试发送）全生命周期留痕；手机号、参数只展示**后端脱敏值**。

### 5.1 筛选栏

| 筛选项 | 取值 |
|---|---|
| 状态 | 全部 / 在途 pending / 成功 success / 失败 failed |
| 场景 | 全部或 9 种 sms_type 之一 |
| 通道 | 全部或某个通道 |
| 来源 | 全部 / 飞连事件 feilian / 测试发送 test |
| 起始时间 / 结束时间 | 浏览器本地日期时间选择器 |

「查询」执行筛选并回到第 1 页；「重置」清空全部条件。每页 50 条，底部分页器显示「第 X-Y 条 / 共 Z 条 · 第 N/M 页」与上一页/下一页按钮。

### 5.2 列表列

发送时间（本地时区）、appSmsId、场景、手机号（脱敏，如 `13****56`）、模板码、状态徽标、回执徽标、耗时。

- 状态：在途（黄）/ 成功（绿）/ 失败（红）；失败行会追加错误分类的灰色小徽标（含「补发次数耗尽」）。
- 回执：`—`（尚无回执，或厂商只回报了排队中/发送中等中间态）/ 已送达 delivered（绿）/ 送达失败 delivery_failed（红）。

### 5.3 详情抽屉

点击任意行（或键盘聚焦后回车）从右侧打开详情，分三组（同时只保留一个抽屉，切换记录会先关闭旧抽屉）：

- **基本信息**：事件 ID、来源、通道（名称）、短信场景、模板码、手机号（脱敏）、参数（脱敏 JSON）、发送时间、更新时间；
- **发送结果**：状态、错误分类、耗时、**补发次数**（首次下发不计，上限 3）、厂商消息 ID、厂商状态码、厂商描述；
- **厂商回执**：回执状态、回执描述、回执序号、回执时间。

点右上角 ✕、按 Esc 或点遮罩关闭。

### 5.4 状态与错误分类词典

| 错误分类（error_kind） | 界面文案 | 处置建议 |
|---|---|---|
| `unbound` | 场景未绑定 | 到场景绑定选择通道与模板码 |
| `binding_disabled` | 绑定已停用 | 需要时打开该场景的启用胶囊 |
| `channel_disabled` | 通道已停用 | 到通道详情点「启用」 |
| `channel_not_found` | 通道不存在 | 通道已被删除，重新绑定现存通道 |
| `invalid_mobile` | 手机号非法 | 核对飞连事件中的号码与国家码 |
| `render` | 配置渲染失败 | 检查映射路径、常量、签名片段配置 |
| `vendor` | 厂商业务失败 | 看「厂商状态码/描述」（`provider_status`/`provider_message`），对照示例厂商错误码词典（0/50001/50002/…，见 [03 · API 接口文档](./03-API接口文档.md) 第 3.4 节） |
| `network` | 网络错误 | 检查出网链路/DNS/TLS/代理；记录保持在途，worker 会自动补发（最多 3 次） |
| `timeout` | 下游超时 | 检查网络或调大单次下发超时（仍受 3 秒约束）；在途记录自动补发 |
| `resend_exhausted` | 补发次数耗尽 | 自动续发 3 次仍未确认，需排查厂商侧后手动触发测试发送验证 |
| `internal` | 内部错误 | 查 journald 日志并联系开发 |

## 6. 典型操作 SOP

### 6.1 首次配置示例厂商通道（约 5 分钟）

1. 「系统设置」：填 Verification Token、确认 Webhook 路径、填对外访问基址、保存；复制完整事件订阅 URL 备用。
2. 「通道 → ＋ 新建通道」：选「HTTP JSON 示例预置」，命名「示例厂商-生产」，创建。
3. 在通道详情「通道常量」补：`appCode`、`orgCode`（非密钥，如厂商需要），`appSecret` 勾密钥并粘贴真实值；核对基址与端口；保存（通过试渲染）。
4. 复制头部「回执地址」，连同凭证申请资料提交示例厂商/客户侧网络团队；如厂商侧支持自定义请求头且回执链路不可信，先在「系统设置 → 厂商回执鉴权 Token」设置 ≥16 字符的 Token 并保存，再把 Token（`X-Receipt-Token` 头）一并交付厂商。
5. 「测试发送」：用自己的手机号、`code` 场景、真实模板码与参数验证端到端可达；失败按错误分类处置。
6. 「场景绑定」：为 `code` 等需要的场景选通道、填模板码、打开启用胶囊，保存。
7. 飞连后台创建事件订阅、粘贴事件订阅 URL 与同一 Token 并保存（本服务须先在线以通过秒级 challenge）；随后触发一次真实登录验证码，在「发送记录」看到 success 与 delivered。

### 6.2 新增/调整一个场景的模板参数顺序

在「场景绑定」目标行改模板码或参数下标（如示例厂商模板参数顺序与飞连相反时填 `1,0`），确保胶囊为启用，「保存绑定」即可，无需重启、不影响其他场景。

### 6.3 紧急停用某类短信

「场景绑定」关闭对应行胶囊 → 保存绑定（该场景之后事件恒 200 但只留痕 `binding_disabled`）；若是通道级故障，则在「通道」详情点「停用」。

### 6.4 轮换 appSecret

「通道」详情 → 通道常量中 `appSecret` 密钥框粘贴新值（留空不改）→ 保存修改（通过试渲染）→ 用「测试发送」验证；旧密钥即刻失效。轮换主密钥（data key）不在界面操作，见部署文档第 5.3/8 节。

### 6.5 日常巡检

看顶部健康角标是否「服务正常」；在「发送记录」筛失败/超时，关注是否出现连续 `network`/`timeout`/`vendor`；必要时结合 `journalctl -u sms-gateway -f`（JSON 脱敏日志）排查。

## 7. 安全与操作须知

- 管理台无应用层鉴权，**切勿把 8080 端口直接暴露公网**；公网入口仅放通 Webhook 与 `/receipts/`，管理访问用内网网段/堡垒机/反代 ACL 限定。
- 密钥类字段页面只回显掩码；所有日志在出口统一脱敏（手机号前 3 后 2 掩码，secret/token/sign 等键全值掩码）。
- 删除通道、停用绑定前先确认影响面；审计记录不因删除通道而清除。
- 配置改动即时热生效，操作即生产变更，请按客户变更流程执行并保留模板/凭证审批记录。

# 00 · 项目概述

| 文档版本 | v1.0 | 软件版本 | v1.0.0 | 日期 | 2026-09-14 |
|---|---|---|---|---|---|

## 1. 项目背景

客户内网部署的飞连（SealSuite）在登录多因子认证（MFA）、初始密码、重置密码、安全告警、访客 Wi-Fi 等场景下，需要向用户手机发送短信通知，短信通道指定为**示例短信平台**。同时，客户未来可能替换或新增其他短信厂商。

飞连支持将本系统配置为「订阅短信通知事件」的第三方代发方：事件发生时，飞连以标准 HTTP Webhook 把 `notify.v1.sms` 事件推送到本系统。本系统负责接收、校验、按可配置规则转换为下游厂商的 HTTP 报文并完成发送，同时处理厂商异步回执、全量留痕与可视化排查。

由于运行环境为客户内网 **headless Ubuntu 服务器（无显示器、无浏览器、无外网、无 Node）**，系统被设计为**单二进制、前端资源内嵌、浏览器远程管理**的常驻服务。

## 2. 项目目标

1. 正确接收飞连事件订阅：URL 有效性 challenge 秒级回显、Verification Token 来源校验、事件结构解析、可选加密信封兼容。
2. 提供**厂商无关的通用 HTTP 短信通道引擎**：请求方法/地址/头、鉴权、**请求体字段映射表**、签名、响应判定、回执映射全部通过 WebUI 表单配置并持久化到 SQLite，**热生效、不改代码、不发版**。
3. 内置「HTTP JSON 示例预置」模板（preset id：`http_json_v1`），一键载入即得到报文映射、签名、响应判定与回执的完整配置，仅需补录基址、凭证与模板码。
4. 幂等可靠：飞连在约 7.1 小时窗口内的重推绝不重复下发；对飞连始终 3 秒内回 HTTP 200；下游失败仅留痕，不触发飞连重推。
5. 提供 PC 内网浏览器可用的管理台：系统设置、通道管理、场景绑定、发送记录与回执、测试发送。
6. 安全：通道密钥 AES-256-GCM 密文存储、界面掩码、日志强制脱敏；可选管理端 CIDR 白名单。
7. 易交付：单二进制 + systemd，无外部中间件依赖（SQLite 内嵌、纯 Go 驱动、CGO-free）。

## 3. 业务场景

飞连在以下 9 种短信场景（`sms_type`）产生事件，本系统按「场景 → 通道 + 模板 + 参数重排」的绑定关系转发：

| sms_type | 含义（飞连官方标识，含官方拼写） |
|---|---|
| `code` | 登录/操作验证码 |
| `init_password` | 初始密码 |
| `reset_password` | 重置密码 |
| `alert` | 安全告警 |
| `guest_wifi` | 访客 Wi-Fi |
| `password_expiration` | 密码过期提醒 |
| `accout_expire` | 账号过期提醒（**飞连官方拼写即为 accout**） |
| `wifi_info` | Wi-Fi 信息 |
| `exchange_mfa` | Exchange 多因子认证 |

本期至少完成 `code` 场景与示例厂商通道的绑定上线；其余场景在同一套表单机制下配置即可启用。

## 4. 系统边界

### 4.1 在范围内

- 飞连 → 本系统方向的 Webhook 事件接入（不调用飞连任何 OpenAPI）。
- 本系统 → 下游短信厂商方向的标准 HTTP（JSON）发送。
- 厂商 → 本系统方向的异步送达回执接收与回写。
- 通道/绑定/飞连接入参数的 WebUI 配置、SQLite 持久化与热生效。
- 幂等去重、失败留痕、结构化脱敏日志、健康检查、优雅退出。
- headless Ubuntu 的 systemd 部署与全链路自检工具。

### 4.2 不在范围内（Non-Goals）

- 飞连事件订阅的 Kafka 模式（仅 Webhook）。
- 调用飞连 OpenAPI（无需 access_token，数据流仅飞连 → 本系统）。
- 验证码的生成与校验（由飞连负责），本系统只传递短信内容。
- 接收手机用户上行短信（回复短信）；不使用示例厂商 Java SDK。
- WebUI 登录鉴权、多用户/角色/审计/多租户（依赖内网可信边界 + 可选 CIDR）。
- 请求体仅支持 JSON（请求头任意可配）；不支持 SOAP/XML、form-urlencoded、厂商私有 TCP。
- 飞连 Encrypt Key 加密推送的生产启用（界面与代码保留兼容能力，默认明文）。
- 多通道轮询/故障切换；高可用集群（单机 + 单 SQLite 实例）。

## 5. 运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | Ubuntu 20.04+（Debian 系同理）；x86_64 主目标，arm64 附带 |
| 部署形态 | 单二进制常驻进程，systemd 托管；无图形界面 |
| 运行时依赖 | 无（CGO-free 静态链接；SQLite 为纯 Go 驱动内嵌） |
| 管理入口 | 运维 PC 的现代浏览器，内网访问 `http://<主机IP>:<端口>/`，服务器自身无需浏览器 |
| 网络 | 与飞连同内网可达；出网到示例厂商 `sms.example.com:1443`（策略待客户落实） |
| 构建工具链（仅构建机需要） | Go 1.26.x、GNU Make、bash；目标机无需 Go |

## 6. 术语与缩写

| 术语 | 说明 |
|---|---|
| 飞连 / SealSuite | 客户内网部署的企业安全办公平台，短信事件来源方 |
| 短信网关 / 本系统 | 本交付软件，承接飞连事件并转发下游短信厂商 |
| 通道（Channel） | 一个下游短信厂商的完整 HTTP 适配配置集合 |
| 字段映射（Body Mapping） | 「源值 → 目标 JSON 点分路径」的表单行，引擎据此组装厂商请求体 |
| 场景绑定（Binding） | `sms_type` 与「通道 + 模板码 + 参数下标序列」的对应关系 |
| 预置（Preset） | 内置的厂商配置模板，本期为 `http_json_v1` |
| appSmsId | 我方消息幂等键，取飞连 `event_id`（批量为 `event_id-i`） |
| challenge | 飞连保存订阅时的 URL 有效性校验随机串，须原样回显 |
| Verification Token | 飞连事件头中的来源校验令牌，与系统设置恒定时间比对 |
| Encrypt Key | 飞连可选的事件体 AES 加密密钥（本期默认不启用） |
| data key | 通道密钥的主密钥（AES-256-GCM，32 字节），不进库、不进 Git |
| nonce | 示例厂商要求的 5–6 位随机数字串 |
| 回执（Receipt/DLR） | 厂商异步回传的短信送达状态（如示例厂商 `DELIVRD`） |
| WAL | SQLite Write-Ahead Logging 日志模式 |

## 7. 干系人与职责

| 角色 | 职责 |
|---|---|
| 客户业务/安全负责人 | 确认短信场景、模板文案、管理端网段与上线窗口 |
| 实施工程师 | 部署软件、在 WebUI 配置飞连接入参数与示例厂商通道、配置飞连后台订阅、组织联调 |
| 客户网络/安全管理员 | 开通出网防火墙/代理、配置回执入内网映射、（可选）管理端 CIDR |
| 示例厂商平台对接人 | 发放 appCode/appSecret/orgCode、审核 templateCode、登记回执 URL |
| 运维人员 | 日常巡检、查看日志与发送记录、处理失败短信、备份数据库与主密钥 |
| 终端用户 | 接收短信（间接受益方） |

## 8. 关键约束与假设

- 单批事件通常 1 条，逐条同步发送满足飞连 3 秒响应预算（下游单次超时默认 2000ms）。
- 飞连 `code` 场景 `params` 至少含验证码；与示例厂商模板参数顺序不一致时，用绑定的参数下标序列修正。
- 管理使用人员均处于内网可信位置，安全边界为网络分区 + 可选 CIDR；系统不提供应用层登录。
- 未来厂商差异限定在「JSON over HTTP + 三种内置签名策略」；超出范围（XML、新签名算法）按既有接口扩展策略插件，表单模型不变。
- 示例厂商回执现状无验签，系统记录回执来源直连 IP；如示例厂商后续补充验签规则，在回执配置区扩展即可。

## 9. 交付结论

本软件已完成需求规格中全部在范围内功能（FR-1～FR-15），通过 171 个自动化测试用例、竞态检测、静态检查、双架构交叉编译与 10 步全链路冒烟验证；核心包语句覆盖率 84.2%。详细结果见 [07 · 测试报告](./07-测试报告.md)。示例厂商真实凭证与模板为客户侧申请项，到位前以预置占位配置与厂商桩完成全部可测性验证，到位后仅需在 WebUI 补录即可上线。

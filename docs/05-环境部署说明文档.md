## 1. 部署形态总览

```
                    ┌──────────────────────────────────────────────┐
  飞连云（事件订阅） │  HTTPS 公网/专线  →  客户侧反代/防火墙映射     │
  示例厂商云（异步回执） │  HTTPS 公网        →  客户侧反代/防火墙映射     │
                    └───────────────┬──────────────────────────────┘
                                     │ HTTP（内网，可选 TLS 卸载于反代）
                                     ▼
                    ┌──────────────────────────────────────────────┐
                    │   Ubuntu 主机（headless，systemd）             │
                    │   nginx（可选，TLS/公网入口）  :443 → :8080     │
                    │   ┌────────────────────────────────────────┐  │
                    │   │ sms-gateway（单二进制，静态链接，无依赖）│  │
                    │   │ WebUI / /api / Webhook / /receipts      │  │
                    │   └───────────────┬────────────────────────┘  │
                    │                   │ sqlite 文件（WAL）          │
                    │                   ▼                            │
                    │        /var/lib/sms-gateway/sms.db             │
                    └───────────────┬──────────────────────────────┘
                                     │ HTTPS 出网 sms.example.com:1443
                                     ▼
                              示例短信平台
```

关键特征：

- **单二进制、零运行时依赖**：Go 纯静态编译（CGO-free），目标机无需安装 JDK、Python、Node、数据库或任何 so 库；SQLite 驱动为纯 Go 实现。
- **headless**：目标机无图形界面，管理面是浏览器访问的内嵌 WebUI（[06 · 用户操作手册](./06-用户操作手册.md)）。
- **业务配置零文件**：引导配置只有 6 个启动项；飞连参数、通道、绑定全部在 WebUI 配置并存入 SQLite，热生效、不重启、不重新发版。

## 2. 软硬件要求

### 2.1 目标机（生产/测试运行环境）

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Ubuntu 20.04 LTS 及以上（Debian 11+ 同理） | x86_64 为主目标，arm64 已提供交叉编译产物 |
| init 系统 | systemd | 一键安装脚本依赖 `systemctl` 注册服务；无 systemd 的容器仅完成文件安装 |
| CPU / 内存 | 建议 1 vCPU / 512 MB 起 | 事件驱动、逐条同步下发，负载极低；实际用量以短信峰值为准 |
| 磁盘 | 建议 2 GB 以上数据分区 | 程序约 16 MB；数据库随发送记录线性增长（见 [04 · 数据库设计文档](./04-数据库设计文档.md) 第 10 节） |
| 网络 | 可出网到 `sms.example.com:1443`；入站可达飞连云与示例厂商回执 | 详见第 7 节联调网络清单 |
| 系统命令 | `bash`、`install`（coreutils）、`systemctl`；`openssl` 可选 | 无 openssl 时密钥生成自动回退 `/dev/urandom` |
| 端口 | 一个非特权 TCP 端口（默认建议 **8080**） | 非 root 运行，禁止使用 1024 以下端口 |
| 时间同步 | 建议开启 NTP（`timedatectl` / chrony） | 请求时间戳取本机毫秒时钟 |

> 运行中进程身份：系统用户 `sms-gateway`（`/usr/sbin/nologin`，无家目录），不持有任何 Linux capability。

### 2.2 构建机（编译产物的机器，可与目标机不同）

| 项 | 要求 |
|---|---|
| Go 工具链 | **Go 1.26.3**（见 [go.mod](../go.mod)；同系列更新版本亦可） |
| 构建命令 | `make`、`go build`（交叉编译无需 gcc，已设置 `CGO_ENABLED=0`） |
| 网络 | 首次构建需访问 Go module 代理拉取 4 个依赖（`go mod download`）；内网可设 `GOPROXY=https://goproxy.cn,direct` |
| 冒烟依赖 | `bash` 3.2+、`curl`、`python3`（Ubuntu server / macOS 均自带，仅自检用） |

构建机可以是开发用 macOS 或任意 Linux，产物经 scp/制品库传到目标 Ubuntu 主机安装。

## 4. 一键安装（install.sh）

### 4.1 安装命令

```bash
# 方式 A：把源码或二进制传到目标机后，在仓库根执行（幂等，可重复执行）
sudo deploy/install.sh --bin bin/sms-gateway-linux-amd64

# 方式 B：先预览将执行的全部动作，不改动系统（可非 root）
deploy/install.sh --dry-run --bin bin/sms-gateway-linux-amd64

# 方式 C：不传 --bin 时，脚本自动按顺序寻找
#   bin/sms-gateway-linux-amd64，其次 bin/sms-gateway
sudo deploy/install.sh
```

参数：`--bin PATH`（指定二进制）、`--dry-run|-n`（只打印动作）、`--help|-h`。

### 4.2 安装脚本执行的 6 个动作（全部幂等）

1. 创建系统用户/组 `sms-gateway`（`useradd --system --no-create-home --shell /usr/sbin/nologin`），已存在则跳过；
2. 建目录：`/etc/sms-gateway`（0750 root:sms-gateway）、`/var/lib/sms-gateway`（0750 sms-gateway:sms-gateway）；
3. **仅首装**生成 32 字节随机主密钥到 `/etc/sms-gateway/sms-gateway.env`（0640 root:sms-gateway，`openssl rand -base64 32`，回退 `/dev/urandom`）；已存在则**保留不动**；
4. **仅首装**安装引导配置 `/etc/sms-gateway/config.yaml`（0640）；已存在则**保留不动**；
5. 二进制原子安装到 `/usr/local/bin/sms-gateway`（0755 root:root，升级时直接覆盖）；
6. 安装 unit 到 `/etc/systemd/system/sms-gateway.service`（0644），随后 `daemon-reload` + `enable` + `restart`，并检查 `is-active`。

脚本结尾打印 WebUI 入口：`http://<本机IP>:8080/`。若服务未进入 active，脚本以非 0 退出并提示查看 journal。

### 4.3 安装后的文件与权限清单

| 路径 | 权限 / 属主 | 说明 |
|---|---|---|
| `/usr/local/bin/sms-gateway` | 0755 root:root | 主程序二进制 |
| `/etc/systemd/system/sms-gateway.service` | 0644 root:root | systemd 单元 |
| `/etc/sms-gateway/config.yaml` | 0640 root:sms-gateway | 引导配置（仅 6 个启动项） |
| `/etc/sms-gateway/sms-gateway.env` | 0640 root:sms-gateway | 主密钥环境文件（**不入库、不覆盖、需单独备份**） |
| `/var/lib/sms-gateway/` | 0750 sms-gateway:sms-gateway | 唯一可写数据目录 |
| `/var/lib/sms-gateway/sms.db`（+`-wal`、`-shm`） | 进程 umask 0077 | SQLite 数据库，首启自动建表迁移 |

> 因安装脚本通过环境文件注入了 `SMSGW_SECRETS_DATA_KEY`，正常安装的系统**不会**在数据目录生成 `data.key`；只有不设该环境变量直接启动二进制时，才会在数据库同目录自动生成 0600 的 `data.key`（见第 5.3 节）。

### 4.4 首次启动后的初始化顺序

主进程 [main.go](../cmd/sms-gateway/main.go) 启动顺序：加载引导配置 → 初始化 Zap 日志 → 解析数据密钥 → 打开 SQLite 并执行迁移（v1/v2 自动升级）→ 载入配置快照 → 装配编排服务与内嵌 WebUI → 开始监听；收到 SIGTERM/SIGINT 后 **5 秒优雅关闭**（HTTP header 读取超时 10 秒，下游下发硬上限 60 秒）。

## 5. 配置说明

### 5.1 配置分层与优先级

```
环境变量 SMSGW_*   （最高优先级，systemd 经 EnvironmentFile 注入）
        ▲ 覆盖
引导 YAML /etc/sms-gateway/config.yaml  （仅启动级 6 项）
        ▲ 完全独立
SQLite 业务配置（飞连参数 / 通道 / 绑定，WebUI 维护，热生效）
```

- YAML 使用严格解析（`KnownFields`），写错键名会在启动期直接报错，防止静默忽略。
- YAML 与环境变量都不是业务配置入口；**改通道/飞连参数请用 WebUI，不要编辑 YAML**。

### 5.2 引导配置逐项说明

| YAML 键 | 环境变量 | 必填 | 默认 | 取值/校验 |
|---|---|---|---|---|
| `server.listen` | `SMSGW_SERVER_LISTEN` | 是 | 无 | `host:port`，如 `:8080`、`127.0.0.1:8080`；格式非法启动失败 |
| `server.admin_cidrs` | `SMSGW_SERVER_ADMIN_CIDRS` | 否 | 空（不限制） | CIDR 逗号分隔，如 `10.0.0.0/8,192.168.0.0/16`；**只信直连 IP，忽略 X-Forwarded-For** |
| `sqlite.path` | `SMSGW_SQLITE_PATH` | 是 | 无 | 数据库文件绝对路径 |
| `log.level` | `SMSGW_LOG_LEVEL` | 否 | `info` | `debug` / `info` / `warn` / `error` |
| `log.format` | `SMSGW_LOG_FORMAT` | 否 | `json` | `json`（生产，journald 采集）/ `console`（排障） |
| `secrets.data_key` | `SMSGW_SECRETS_DATA_KEY` | 否 | 自动生成 | base64 编码的 32 字节主密钥；非空时优先，且不产生密钥文件 |
| `secrets.key_path` | `SMSGW_SECRETS_KEY_PATH` | 否 | `<数据库目录>/data.key` | 密钥文件路径；首启缺失自动生成（0600） |

命令行参数：

```bash
/usr/local/bin/sms-gateway --config /etc/sms-gateway/config.yaml
# --config 留空则纯环境变量启动（容器场景）
```

`admin_cidrs` 生效边界：`/api/*` 与 WebUI 页面受网段守卫；`POST /<webhook路径>`、`POST /receipts/{channel_id}`、`GET /health` 不经 CIDR 限制（供飞连云/示例厂商云访问）。

### 5.3 数据密钥（主密钥）红线

- 用途：加密通道配置中的厂商密钥（如示例厂商 `appSecret`），AES-256-GCM 信封，密文入库；密钥本身绝不明文落数据盘。
- 来源优先级：`SMSGW_SECRETS_DATA_KEY` 环境变量 → `key_path` 文件 → 自动生成 0600 文件。
- **备份红线**：备份数据库时必须同时、分开备份主密钥（环境文件或 data.key）。主密钥丢失不会导致程序无法启动，但历史通道密文将无法解密，需在 WebUI 重新录入厂商密钥。
- 轮换：本期不提供自动轮换；轮换需在 WebUI 重新录入密钥后改环境变量并重启（实施前先备份）。

### 5.4 业务设置（WebUI，热生效）

以下在 WebUI「系统设置」页维护，存入 `system_settings` 单行，保存即热生效、无需重启：

| 设置 | 默认 | 校验/说明 |
|---|---|---|
| Verification Token | 空 | 飞连事件订阅校验令牌 |
| Encrypt Key | 空 | 留空=明文信封；配置后强制按密文解析，防降级 |
| Webhook 路径 | `/feilian/sms/events` | 运行时按路径匹配，可改为难猜路径 |
| 对外访问基址 public_base_url | 空 | 用于展示/拼接完整回调与回执 URL |
| 下游下发超时 | 2000 ms | 允许范围 **100 ~ 60000**；受飞连「3 秒内必须回 200」约束，建议 ≤2500 |
| pending 僵死补发阈值 | 120000 ms | 允许范围 **1000 ~ 86400000**；pending 超阈值的同一事件允许续发一次 |

时序约束（联调须知，源自飞连官方文档）：订阅保存时的 `url_verification` 必须在 **1 秒内**原样返回 challenge；事件推送须 **3 秒内**返回 HTTP 200，否则飞连按 15 秒/5 分钟/1 小时/6 小时重推最多 4 次——本服务对任何事件都快速回 200，失败仅留痕，配合 appSmsId 幂等保证重推安全。

## 6. systemd 服务管理

### 6.1 常用命令

| 操作 | 命令 |
|---|---|
| 查看状态 | `systemctl status sms-gateway` |
| 启动 / 停止 / 重启 | `sudo systemctl start|stop|restart sms-gateway` |
| 开机自启（安装时已 enable） | `sudo systemctl enable sms-gateway` |
| 查看实时日志 | `journalctl -u sms-gateway -f` |
| 查看最近 100 行 | `journalctl -u sms-gateway -n 100 --no-pager` |
| 本次启动日志 | `journalctl -u sms-gateway -b --no-pager` |

### 6.2 单元关键策略（[sms-gateway.service](../deploy/sms-gateway.service)）

- `Restart=on-failure`、`RestartSec=5`：崩溃 5 秒自动拉起；`TimeoutStopSec=10` 配合进程内 5 秒优雅退出。
- 日志：stdout/stderr 全部进 journald，`SyslogIdentifier=sms-gateway`，默认 JSON 结构化输出且出口脱敏。
- 最小权限加固：`NoNewPrivileges`、`CapabilityBoundingSet=`（空，零 capability）、`PrivateTmp`、`PrivateDevices`、`ProtectSystem=full`、`ProtectHome`、`ProtectKernelModules/Logs/ControlGroups/Clock`、`RestrictSUIDSGID/Realtime/Namespaces`、`RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX`、`MemoryDenyWriteExecute`、`SystemCallArchitectures=native`、`RemoveIPC`、`UMask=0077`。
- 唯一可写位置：`ReadWritePaths=/var/lib/sms-gateway`；`WorkingDirectory=/var/lib/sms-gateway`。
- `After=network-online.target` / `Wants=network-online.target`：网络就绪后启动。

### 6.3 健康检查

服务启动后（无需鉴权、不经 CIDR）：

```bash
curl -s http://127.0.0.1:8080/health
# 预期精确输出：{"status":"ok"}
```

WebUI 页面自身也会每 20 秒静默探测一次 `/api/health` 显示在线状态。

## 7. 网络与联调清单（上线前必须落实）

### 7.1 网络矩阵

| 方向 | 源 → 目的 | 端口/协议 | 用途 | 本期默认 |
|---|---|---|---|---|
| 出网 | 本机 → `sms.example.com` | TCP **1443** HTTPS | 示例厂商 `/sms/send` 下发 | **需客户开通防火墙/代理** |
| 入站 | 飞连云 → 本机 Webhook | 公网可达的 HTTPS（建议反代 443 → 内网 8080） | 事件订阅 + challenge | **需客户提供公网/专线入口** |
| 入站 | 示例厂商云 → `/receipts/{channel_id}` | 公网可达 HTTPS | 异步送达回执，申请凭证时填报该 URL | **需客户提供公网入口** |
| 入站 | 内网运维网段 → WebUI/`/api` | TCP 8080 HTTP | 管理面 | 用 `admin_cidrs` 限定网段 |

进程本身只说 HTTP、不内置 TLS（需求决策）。若入口暴露公网，标准做法是在前置 nginx/网关上做 TLS 卸载与 AllowList，再转发到 `127.0.0.1:8080`；注意 CIDR 守卫依据直连地址，反代场景应让网关只监听 `127.0.0.1` 并在 nginx 层做来源控制。

### 7.2 主机防火墙示例（ufw）

```bash
# 仅内网网段访问管理口
sudo ufw allow from 10.0.0.0/8 to any port 8080 proto tcp
# 若前置 nginx 同机反代，8080 甚至不必对网段开放，只放行 443
sudo ufw allow 443/tcp
sudo ufw enable
```

### 7.3 上线联调检查单

1. [ ] 出网策略：`curl -v https://sms.example.com:1443/` 在本机可建连（具体路径由示例厂商定义，能完成 TLS 握手即可）。
2. [ ] 入站策略：飞连云能访问到 Webhook 的完整公网 URL；在飞连后台创建事件订阅、勾选短信通知事件，填入 URL 与 Verification Token（保存瞬间即发起 challenge，必须先把本服务装好并在 WebUI 配好 Token/路径）。
3. [ ] 示例厂商回执：确定回执公网 URL（形如 `https://<域名>/receipts/<示例厂商通道ID>`），申请凭证时向示例厂商填报；通道 ID 在 WebUI 建完通道后从浏览器/接口获得。
4. [ ] 厂商凭证：`appCode`、`appSecret`、`orgCode`（如厂商要求组织编码）、`templateCode` 申请与模板审核完成；凭证到位前以预置占位配置演练，到位后在 WebUI 从 `http_json_v1` 预置建通道并补录。
5. [ ] 参数顺序：确认示例厂商 `code` 模板参数顺序，与飞连不一致时在绑定中配置「参数下标序列」。
6. [ ] 监听端口与管理网段：确定 `server.listen` 与 `SMSGW_SERVER_ADMIN_CIDRS`。
7. [ ] 时钟：确认 NTP 已同步。
8. [ ] 备份：把 `/etc/sms-gateway/sms-gateway.env` 纳入客户密钥管理系统单独备份。

### 7.4 与 mockvendor 对通（无外部依赖的预演）

在等待示例厂商凭证/防火墙期间，可用交付的厂商桩在本机完整演练配置与数据流（桩为测试组件，**不要装到生产机**）：

```bash
make smoke                      # 官方 10 步冒烟，临时目录、临时端口，零污染
# 自定义端口：
GW_PORT=18090 MOCK_PORT=19091 bash deploy/smoke/run.sh
# 切换日志格式验证：
SMSGW_LOG_FORMAT=json bash deploy/smoke/run.sh
```

冒烟覆盖：健康检查 → 设置 → 预置建通道 → 补凭证（保存前试渲染）→ 绑定 → challenge 秒级回显 → 事件下发（校验 40 位签名与掩码手机号）→ 幂等重放 → 未绑定场景留痕 → 回执精确响应与回写 → 厂商业务失败归类 → records 校验。任一步失败立即非 0 退出并打印网关日志尾部。

## 8. 升级、回滚与卸载

### 8.1 升级（幂等）

```bash
# 1) 升级前先备份（数据库 + 环境文件分开存）
sudo sqlite3 /var/lib/sms-gateway/sms.db "PRAGMA wal_checkpoint(TRUNCATE);"
sudo cp /var/lib/sms-gateway/sms.db /backup/sms-$(date +%F).db
sudo cp /etc/sms-gateway/sms-gateway.env /backup/sms-gateway.env.$(date +%F)

# 2) 构建新版本并重新运行安装脚本（二进制原子覆盖，配置/密钥/数据库均不动）
make build-linux-amd64
sudo deploy/install.sh --bin bin/sms-gateway-linux-amd64   # 自动 daemon-reload + restart
```

数据库迁移在启动时自动执行（v1→v2 已内置），向后兼容；升级后用 `curl /health` 与 `make smoke`（在另一台机器或临时端口）复验。

### 8.2 回滚

保留上一版二进制即可秒级回滚（install.sh 不保留旧版本，需自行在升级前备份 `/usr/local/bin/sms-gateway`）：

```bash
sudo cp /usr/local/bin/sms-gateway /backup/sms-gateway.prev
# 回滚时：
sudo install -m 0755 /backup/sms-gateway.prev /usr/local/bin/sms-gateway
sudo systemctl restart sms-gateway
```

> 注意：若新版本已执行不可逆 schema 迁移，回滚二进制前需评估数据库兼容性；当前 v1/v2 迁移仅做新增，不影响旧版本读取新增列以外的数据。

### 8.3 卸载（无内置卸载命令，按以下手工步骤）

```bash
# 1) 停服并取消开机自启
sudo systemctl disable --now sms-gateway
# 2) 删除 unit 与二进制
sudo rm -f /etc/systemd/system/sms-gateway.service /usr/local/bin/sms-gateway
sudo systemctl daemon-reload
# 3) 按需删除配置/密钥/数据（删前确认已备份！）
sudo rm -rf /etc/sms-gateway /var/lib/sms-gateway
# 4) 按需删除系统账号
sudo userdel sms-gateway
```

## 9. 备份与恢复要点

- 数据库在线备份推荐 `PRAGMA wal_checkpoint(TRUNCATE);` 后复制 `sms.db`，或使用 `sqlite3 .backup`；停服窗口可直接复制 `sms.db`/`-wal`/`-shm` 三文件。
- 主密钥（`sms-gateway.env` 或 data.key）必须**异机、异介质**单独备份，二者分离存放。
- 恢复：放回数据库与内容一致的主密钥，保持属主 `sms-gateway:sms-gateway`、目录 0750，`systemctl restart sms-gateway`。
- 完整性校验：`PRAGMA integrity_check;`、`PRAGMA foreign_key_check;`。

完整字段级说明见 [04 · 数据库设计文档](./04-数据库设计文档.md) 第 9 节。

## 10. 故障排查

| 现象 | 排查方向 |
|---|---|
| 安装脚本退出码 1，提示服务未 active | `journalctl -u sms-gateway -n 50 --no-pager`；常见为端口占用（`ss -lntp | grep 8080`）、`listen` 格式错误、`sqlite.path` 目录不可写 |
| 启动 panic「加载引导配置失败」 | YAML 键名拼写错误（严格解析）或值非法；错误信息带字段名，按提示修正 |
| 端口监听失败 `permission denied` | 使用了 1024 以下端口；服务以非特权用户运行，改用 8080 等高位端口 |
| 浏览器打不开 WebUI，接口返回 403 | 来源 IP 不在 `admin_cidrs`；注意经反代时识别的是直连 IP（XFF 不被信任） |
| WebUI 能开但提示异常/通道密钥报错 | 主密钥与密文不匹配（换过 env 或漏恢复 data.key）；需在 WebUI 重新录入厂商密钥 |
| 飞连保存订阅失败/challenge 不通过 | 服务未公网可达、Token 不一致、Webhook 路径不一致；challenge 必须 1 秒内原样回显，前置代理不得缓冲或改写 body |
| 飞连重复推送同一事件 | 属官方重推机制；本服务幂等去重，records 中同一 event_id 不会重复下发，可据 `app_sms_id` 核对 |
| 短信记录 `error_kind=timeout/network` | 出网到 `sms.example.com:1443` 不通或过慢；检查防火墙/代理与 `downstream_timeout_ms` |
| 短信记录 `error_kind=vendor` | 示例厂商已响应但返回非 0 错误码；看记录中 `provider_message`，对照 [03 · API 接口文档](./03-API接口文档.md) 示例厂商错误码表（50001/50002/…） |
| 回执不到达/不回写 | 回执 URL 不通、通道 ID 拼错；示例厂商要求响应体必须精确为 `{"status":0,"message":"success"}`，本服务已内置；用 curl 模拟 POST 到 `/receipts/{id}` 自验 |
| 需要更详细日志 | 临时设 `SMSGW_LOG_LEVEL=debug`（改 env 后 restart；或在配置文件调整），排障后调回 `info`；`SMSGW_LOG_FORMAT=console` 便于人读 |
| 怀疑日志泄密 | 所有出口日志已统一脱敏（手机号前 3 后 2 掩码、secret/token/sign 等键全值掩码）；自查方法与变异验证见 [07 · 测试报告](./07-测试报告.md) |

日常操作与界面字段说明见 [06 · 用户操作手册](./06-用户操作手册.md)；接口与报文细节见 [03 · API 接口文档](./03-API接口文档.md)。

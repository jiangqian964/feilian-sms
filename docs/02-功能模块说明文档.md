## 2. 启动引导模块（FR-1）

- 只承载「进程启动级」配置：监听地址、SQLite 路径、日志级别/格式、数据密钥来源、管理端 CIDR。
- 所有业务配置（飞连参数、通道、绑定）存 SQLite、在 WebUI 管理，不进入引导文件，业务变更不发版、不登主机。
- 配置来源优先级：**环境变量 `SMSGW_*` 覆盖 YAML**；`--config` 为空时可纯环境变量启动。
- 启动期对非法项一次性给出中文字段级错误并快速失败。

| YAML 键 | 环境变量 | 默认/约束 |
|---|---|---|
| `server.listen` | `SMSGW_SERVER_LISTEN` | 必填，形如 `:8080` 或 `127.0.0.1:8080` |
| `server.admin_cidrs` | `SMSGW_SERVER_ADMIN_CIDRS` | 可选，逗号分隔；非法 CIDR 启动报错；留空不限 |
| `sqlite.path` | `SMSGW_SQLITE_PATH` | 必填，数据库文件路径 |
| `log.level` | `SMSGW_LOG_LEVEL` | `debug/info/warn/error`，默认 info |
| `log.format` | `SMSGW_LOG_FORMAT` | `json/console`，默认 json |
| `secrets.data_key` | `SMSGW_SECRETS_DATA_KEY` | base64 的 32 字节，优先且不落盘 |
| `secrets.key_path` | `SMSGW_SECRETS_KEY_PATH` | 默认与 DB 同目录 `data.key`，首启缺失自动生成（0600） |

数据密钥解析：内联 base64 → 解码为 32 字节；否则读密钥文件；文件不存在则用 crypto/rand 生成 32 字节并以 0600 写入。主密钥不进库、不进 Git；备份数据库时必须单独安全备份该密钥，否则已存通道密钥无法解密。

生命周期：监听 SIGTERM/SIGINT，5 秒优雅关闭（停接新连接、等待在途），超时强关；`Restart=on-failure` + 5s 由 systemd 兜底拉起。

## 3. 飞连接入模块（FR-2、FR-3、FR-9、FR-14）

### 3.1 URL 有效性握手
- 飞连保存订阅时 POST `{"challenge","token","type":"url_verification"}`，可能为加密信封。
- token 校验通过后，**1 秒内**把 challenge 值作为响应体**原样**返回（`text/plain`）。token 不符返回 401。

### 3.2 事件接收
- Webhook 路径以系统设置中的 `webhook_path` 在**运行时比对**（默认 `/feilian/sms/events`），因此路径可在界面热改，下一条请求即按新路径生效；旧路径返回 404。
- 请求体上限 1MiB（超限 413）。
- 事件信封：`schema`、`header.{event_id,token,create_time(毫秒字符串),event_type,app_id}`、`data.events[].object`。
- 非短信事件：记录日志后直接回 200，不触发编排。
- `header.token` 与设置中的 Verification Token 做**恒定时间比较**；不符 401 且零下游调用、不产生发送记录。
- 对通过 token 校验的短信事件：无论单条成功失败，**恒回** `{"code":0,"message":"success"}`，HTTP 200，且带 `Cache-Control: no-store`。

### 3.3 加密兼容（本期默认不启用）
- Encrypt Key 留空：仅接受明文信封。
- 收到 `{"encrypt":...}` 加密信封但未配 key：400；配置 key 后仅接受密文（明文被拒，防止降级）。
- 算法与飞连一致：AES-256-CBC，key=SHA256(Encrypt Key)，16 字节随机 IV，密文 base64(iv+ciphertext)，PKCS7；以飞连官方向量验收。

### 3.4 支持的短信场景（9 种，管理面校验白名单）
`code`、`init_password`、`reset_password`、`alert`、`guest_wifi`、`password_expiration`、`accout_expire`（官方拼写）、`wifi_info`、`exchange_mfa`。

短信对象字段：`country_code`（如 +86）、`mobile_number`（不含区号）、`mobile`（含区号）、`sms_type`、`template`（%s 占位）、`params`（按序数组）、`expired_time`（秒）。

## 4. 通用 HTTP 通道引擎（FR-4、FR-5、NFR-6）

通道配置是一个结构化 JSON 对象（在界面按区块表单编辑、以对象而非字符串模板提交落库），顶层七部分：

```jsonc
{
  "request":       { "base_url": "", "url": "", "method": "POST",
                     "content_type": "application/json", "headers": { } },
  "constants":     { "常量名": { "value": "明文值或空", "secret": false } },
  "body_mappings": [ { "target": "...", "source_type": "variable|const|literal",
                       "source": "...", "value_type": "string|number|boolean|raw" } ],
  "sign":          { "strategy": "none|sha1_salt|hmac_sha256", "encoding": "hex|base64",
                     "secret_const": "密钥常量名", "segments": [ ] },
  "response":      { "success_path": "status", "success_value": "0",
                     "msg_id_path": "data.id", "message_path": "message" },
  "mobile_policy": "raw|strip_plus|cc_prefix",
  "receipt":       { "msg_id_path": "smsId", "app_msg_id_path": "appSmsId",
                     "status_path": "status", "delivered_value": "DELIVRD",
                     "message_path": "statusMessage", "seq_no_path": "seqNo",
                     "success_body": "" }
}
```

### 4.1 请求设置（request）
- `method`：POST/GET/PUT 白名单（保存与运行双重归一化：Trim + 大写 + 白名单，默认 POST）。
- `base_url` + `url`：`url` 可用 `${base}/path`；已是绝对地址则原样使用。
- `content_type`：默认 `application/json`（示例厂商预置为 application/json）。
- `headers`：自定义请求头 KV，值支持占位插值（见 4.5 鉴权）。

### 4.2 通道常量（constants）
- 每行 `key → {value, secret}`。非密钥常量明文内联于配置；`secret=true` 的常量值不进配置/库明文，真实值由独立密钥表（AES-GCM）提供。
- 示例预置声明 `appCode`（明文，待填）、`orgCode`（明文，待填，无组织编码可留空）、`appSecret`（密钥，待填）。

### 4.3 请求体字段映射表（body_mappings，核心）
每行四元组：

| 字段 | 取值 | 说明 |
|---|---|---|
| `target` | 点分路径 | 如 `appCode`、`data.mobile`、`params`、`list.0.name`；数字段为数组下标 |
| `source_type` | `variable` / `const` / `literal` | 内置运行时变量 / 通道常量（含密钥）/ 字面值 |
| `source` | 变量名、常量名或字面文本 | 取决于 source_type |
| `value_type` | `string` / `number` / `boolean` / `raw` | raw 为合法 JSON 片段，原样嵌入（用于数组/对象） |

内置运行时变量：

| 变量 | 含义 |
|---|---|
| `appSmsId` | 我方幂等键（飞连 event_id，批量 event_id-i；测试为 test- 前缀） |
| `mobile` | 按号码策略归一化后的号码 |
| `mobileNumber` | 不含国家码号码（飞连原值） |
| `countryCode` | 国家码（如 +86） |
| `smsType` | 场景类型 |
| `templateCode` | 当前绑定上的模板码 |
| `timestamp` | 毫秒时间戳（十进制字符串） |
| `nonce` | 5–6 位随机数字 |
| `sign` | 已计算的签名（先签名后渲染，供映射行引用） |
| `params` | 重排后的整个参数数组（JSON 文本，需配 raw 类型） |
| `param0..paramN` | 重排后按下标的单个参数 |

组装规则：按行构建嵌套 map，遇数字段写切片并自动扩容，最后统一 `json.Marshal` 保证合法 JSON；**重复 target、路径标量/容器冲突、非法变量、常量缺失、值类型转换失败**均报错并定位到具体映射行。

### 4.4 签名（sign）
- `strategy`：
  - `none`：不签名（不产生 sign 变量，无需密钥）。
  - `sha1_salt`：`sign = lowerHex(SHA-1( UTF8(appSecret) || UTF8(待签名串) ))`，单次摘要，小写补零 hex。
  - `hmac_sha256`：HMAC-SHA256，输出编码 `encoding=hex|base64`。
- `secret_const`：参与签名的密钥常量名（必须是 constants 中 `secret=true` 项；none 外必填）。
- `segments`：有序片段，每段 `{ "kind": "literal|variable", "value": "..." }`。示例厂商预置 6 段：字面 `timestamp=` + 变量 `timestamp` + 字面 `&nonce=` + 变量 `nonce` + 字面 `&signData=` + 变量 `appSmsId`。
- 渲染次序：生成变量 → 拼待签名串 → 计算 sign → 组装请求体（故 sign 可被映射引用）。未知策略在保存配置时即被拒绝。

### 4.5 鉴权（经请求头 + 密钥常量表达）
鉴权不使用独立配置块，统一通过 `request.headers` 与密钥常量占位实现，密钥值不落配置明文：
- Bearer：头 `Authorization: Bearer ${const:token}`；
- 静态自定义头：头 `X-Api-Key: ${const:apiKey}`；
- Basic：头 `Authorization: Basic ${constb64:credential}`，其中 credential 以 `user:password` 存为密钥常量，占位自动做 base64。

占位在渲染期替换为明文值（仅存在于内存请求对象），日志出口脱敏会拦截 authorization 等敏感头名。

### 4.6 响应判定（response）
- `success_path`：成功标志取值路径（如 `status`）；与 `success_value`（如 `0`）做数字/字符串**宽松相等**，故 `0` 与 `"0"` 均判成功。
- `msg_id_path`：厂商消息 ID 路径（示例厂商 `data.id`）。
- `message_path`：厂商描述/错误信息路径（示例厂商 `message`）。
- 兼容坏 JSON：响应非 JSON 时，HTTP 2xx 视为成功、非 2xx 失败（不抛错，保留留痕）；响应体解析使用 `json.Number` 以兼容「文档标 String、样例为数字」。

### 4.7 手机号归一化策略（mobile_policy）

| 策略 | 规则 | 适用 |
|---|---|---|
| `cc_prefix`（默认/示例厂商） | 去 `+` 国家码拼接本机号；要求 country_code 形如 +86，否则 invalid_mobile | 示例厂商大陆（+86→86 开头） |
| `strip_plus` | 去掉 `mobile` 开头的 `+` | 要求纯数字但不带国家码前缀的厂商 |
| `raw` | 原样使用飞连 `mobile`（可能含 +） | 自行处理号码格式的厂商 |

### 4.8 回执映射（receipt）
`POST /receipts/{channel_id}` 入站 JSON，按路径提取：厂商短信 ID（`msg_id_path`，示例厂商 smsId）、我方 ID（`app_msg_id_path`，示例厂商 appSmsId）、状态（`status_path`）、状态描述（`message_path`）、序号（`seq_no_path`）；`delivered_value` 为送达成功值集合判定（示例厂商 `DELIVRD`，相等即 delivered，否则 delivery_failed）。`success_body` 为回给厂商的成功响应原文，留空时回示例厂商默认 `{"status":0,"message":"success"}`。

### 4.9 保存前试渲染
创建/更新通道（非预置脚手架态）时，服务端用一组样例输入（大陆手机号 + 一个验证码参数）执行完整渲染但不发真实请求，把错误定位到区块：坏 JSON/坏 URL/非法方法、`config.body_mappings`、`config.sign`、`config.mobile_policy` 等；仅「密钥尚未填写」放行，真实下发时再校验。

## 5. HTTP JSON 示例预置（FR-6，preset id = `http_json_v1`）

一键从预置创建后得到与通用 JSON over HTTP 短信报文约定一致的全套配置，用户只需补凭证值与各绑定的 templateCode：

- 请求：`POST https://sms.example.com:1443/sms/send`（base_url + `${base}/sms/send`），application/json。
- 常量：`appCode`（明文待填）、`orgCode`（明文，如厂商需要）、`appSecret`（密钥待填），预置默认均为空。
- 请求体 9 行映射：`appCode`(const,string)、`appSmsId`(var)、`mobile`(var)、`nonce`(var)、`orgCode`(const)、`params`(var,**raw**)、`sign`(var)、`templateCode`(var)、`timestamp`(var,**number**)。
- 签名：`sha1_salt`，密钥常量 appSecret，6 片段如 4.4。
- 响应：`status==0` 成功、消息 ID `data.id`、描述 `message`。
- 号码策略：`cc_prefix`（大陆号去 + 并以 86 开头）。
- 回执：smsId/appSmsId/status/DELIVRD/statusMessage/seqNo，成功响应默认示例厂商体。
- 错误码留痕：0 成功；50001 手机号非法、50002 签名失败、50003 APP 不存在、50006 appCode 未启用、50007 templateCode 未启用、50008 敏感词、50009 超频、50010 超长。

> 示例厂商公网 HTTP 报文字段表无额外 key；若后续示例厂商明确要求，以「常量 + 头/映射行」增补即可，无需改代码。

## 6. 场景绑定与参数重排（FR-7）

- 每个 `sms_type` 一条绑定：启用开关、通道选择、`template_code`、`param_index`（参数下标序列，留空=原序）。
- 参数重排：飞连 `params` 按下标表重排后再供示例厂商模板使用（如飞连顺序与示例厂商模板不一致，配 `[2,1,0]`）；下标越界归 render 类失败；负下标保存即拒。
- 批量保存采用**全量校验通过后才写库**（拒绝半成品批次）：场景必须在 9 种白名单内、不得重复、通道必须存在、模板码非空。

## 7. 编排与幂等状态机（FR-8、FR-9）

- 幂等键：单事件 `appSmsId=event_id`；批量为 `event_id-下标`；长度 ≥64 拒绝。
- 状态：`pending → success / failed`（终态不可逆）；回执仅回写 `delivery_*`，不改主状态。
- 去重规则：终态记录命中即 skipped；在途 pending 未超 `stale_pending_ms`（默认 120000ms）也 skipped；仅超阈值的 pending 允许续发一次（沿用原记录行）。
- 降级分类（零下游调用即落 failed）：`unbound`（未绑定）、`binding_disabled`、`channel_disabled`、`channel_not_found`、`invalid_mobile`。
- 渲染/下发分类：`render`（映射/签名/参数错误，多为配置问题）、`vendor`（HTTP 2xx 但业务失败）、`network`（连接/DNS/非 2xx）、`timeout`（下游超时）、`internal`。
- 超时取**当前设置** `downstream_timeout_ms`（默认 2000ms），随快照热生效；全部失败仅写记录与日志，Webhook 仍 200。

## 8. 厂商回执模块（FR-10）

- 通道不存在 → 404；回执体坏 JSON 或缺我方 ID 路径 → 400。
- 正常解析后按送达值回写，未知 appSmsId 仅记日志（matched=false）仍回通道成功响应，避免厂商反复重推。
- 记录回执来源直连 IP（不读 XFF）；现状无验签，依赖网络边界可信。

## 9. 测试发送（FR-11）

- 入口 `POST /api/channels/{id}/test`，表单含 template_code、sms_type（默认 code，须为 9 种之一）、country_code、mobile_number、可选 mobile、params。
- 生成 `test-<毫秒>-<随机>` 幂等键、`source=test`，走与真实事件完全相同的渲染/签名/下发/判定/留痕链路；停用通道返回 409。
- 界面有显著「仅限测试号码/测试模板」提示；测试记录可在发送记录按 source=test 筛选。

## 10. 持久化与配置热加载（FR-2、NFR-2）

- SQLite WAL、busy_timeout=5000、单连接 + 写串行锁、短事务；崩溃不造成「成功事件重发」（终态闸门 + pending 阈值）。
- 每次写事务提交后触发快照刷新，整体替换不可变 Snapshot（settings/channels 含解密密钥/bindings）；请求侧 O(1) 读当前快照，Token、webhook 路径、超时、通道与绑定改动**下一条请求生效，无需重启**。
- 通道密钥 AES-256-GCM 密文独立存放；API 仅回掩码 + 是否已设置；空提交不修改、显式清空才置空。

## 11. WebUI 管理台（FR-12、FR-13、AC-14）

PC 内网浏览器访问 `http://<主机IP>:<端口>/`，原生前端 go:embed 内嵌，四个标签视图：

1. **系统设置**：Verification Token、Encrypt Key（掩码/已设置/清空）、webhook 路径、对外基址与「完整回调 URL」一键复制、下游超时、pending 补发阈值。
2. **通道**：List + Detail 双栏；详情按区块表单编辑请求/请求头/常量与密钥/字段映射表（可增删排序、变量下拉）/签名片段构造器/响应映射/号码策略/回执映射，支持从预置新建、启停、删除（二次确认）、测试发送。
3. **场景绑定**：9 种 sms_type 表格行内编辑（通道、模板码、参数下标、启用）。
4. **发送记录**：列表筛选（状态/场景/通道/来源/时间窗）+ 分页 + 详情；呈现脱敏手机号、参数掩码、主状态、厂商信息、回执送达状态与错误分类。

交互与可达性：sticky 居中标题（min-height 72px）、胶囊开关、数字等宽（tabular-nums）、加载态、失败 Toast、ARIA 标签/角色、跳转链接；右上角每 20s 静默健康检查（XHR，不打扰）。

## 12. 日志模块（FR-15、NFR-3、AC-16）

- Zap，生产 JSON、排障 console；字段 level/ts/caller/msg，Error 级带堆栈。
- 出口 Core 统一脱敏（详见架构文档 6.5）：手机号前 3 后 2 星号（保留 86 前缀）、params 整体 `[REDACTED]`、敏感键词表整值替换、消息与堆栈兜底。
- 结构化业务字段只含标识与分类：`event_id/app_sms_id/channel_id/sms_type/outcome/provider_msg_id/delivery_status/error_kind/elapsed_ms/remote_ip`；**不含完整手机号、验证码、密钥、sign、鉴权头**。

## 13. 自检与测试支撑组件

- `cmd/mockvendor`：可配置厂商桩，支持经 `POST /__control` 切换 success/business_error/http_error 模式并转储实收报文，供联调与冒烟（非生产组件，不部署到客户现场也行）。
- `deploy/smoke/run.sh`：全新临时目录起桩 + 网关，10 步串联 健康检查→设置→预置建通道→补凭证试渲染→绑定→challenge→事件转发（断言 40 位签名与掩码手机号）→幂等重放→未绑定降级→回执与业务失败分支；支持 `SMSGW_LOG_FORMAT` 环境变量覆盖以采集 JSON 日志样本。
- `testdata/`：飞连握手/事件、示例厂商响应/回执协议样例，纳入解析回归测试，防止文档与代码漂移。

# 04 · 数据库设计文档

| 文档版本 | v1.0 | 软件版本 | v1.0.0 | 日期 | 2026-09-14 |
|---|---|---|---|---|---|

## 1. 概述

- 数据库引擎：**SQLite**，驱动 `modernc.org/sqlite`（纯 Go，CGO-free），随单二进制内嵌，无需安装数据库服务。
- 数据库文件：由引导配置 `sqlite.path` 指定（生产建议 `/var/lib/sms-gateway/sms.db`）；WAL 模式下同目录另有 `sms.db-wal`、`sms.db-shm`。
- 连接参数（DSN pragma）：`busy_timeout(5000)`、`journal_mode(WAL)`、`foreign_keys(ON)`、`synchronous(NORMAL)`。
- 连接池：`SetMaxOpenConns(1)`，配合应用层写互斥锁，所有写事务短事务、串行提交，读不跨连接看到中间态。
- 时间存储：除飞连原文外，本系统时间列一律为 **Unix 毫秒整数**；布尔以 INTEGER 0/1 存储；JSON 结构以 TEXT 存储。
- 敏感数据：通道密钥不明文入库（AES-256-GCM 密文，见第 7 节）；手机号与短信参数仅以脱敏形态入 `sms_send`。

## 2. 表清单与关系

| 表 | 用途 | 引入版本 |
|---|---|---|
| `system_settings` | 系统设置单行（飞连接入参数、超时阈值） | v1 |
| `channels` | 短信通道定义与结构化配置 | v1 |
| `channel_secrets` | 通道密钥密文（与通道配置分离） | v1 |
| `bindings` | sms_type → 通道/模板/参数下标 绑定 | v1 |
| `sms_send` | 短信发送全生命周期留痕（幂等状态机） | v2 |

关系：
```
system_settings (id 恒为 1)
channels (1) ───< channel_secrets   (ON DELETE CASCADE，主键复合 channel_id+name)
channels (1) ───< bindings          (逻辑外键 channel_id；绑定表 FK 声明并级联)
sms_send.channel_id ──引用── channels.id（留痕不声明强外键，通道删除后记录保留）
```
> 说明：`bindings.channel_id` 声明了 `REFERENCES channels(id) ON DELETE CASCADE`；`sms_send` 作为审计留痕，不随通道删除而清除，事件处理期对缺失通道归类为 `channel_not_found`。

## 3. 表结构详细设计

### 3.1 system_settings（系统设置，单行 id=1）

| 列 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| id | INTEGER | PRIMARY KEY，CHECK(id=1) | 固定单行 |
| feilian_verification_token | TEXT | NOT NULL DEFAULT '' | 飞连 Verification Token（普通接入参数，明文存储） |
| feilian_encrypt_key | TEXT | NOT NULL DEFAULT '' | 飞连 Encrypt Key（本期默认空=明文；存储形态见 7.3） |
| webhook_path | TEXT | NOT NULL DEFAULT '/feilian/sms/events' | 事件订阅路径，运行时热匹配 |
| public_base_url | TEXT | NOT NULL DEFAULT '' | 对外访问基址，用于拼接回调/回执 URL |
| downstream_timeout_ms | INTEGER | NOT NULL DEFAULT 2000 | 单次下游下发超时（毫秒），热生效 |
| stale_pending_ms | INTEGER | NOT NULL DEFAULT 120000 | pending 僵死补发阈值（毫秒） |
| updated_at | INTEGER | NOT NULL DEFAULT 0 | 最近更新时间（毫秒） |

首次迁移插入占位列：`INSERT OR IGNORE INTO system_settings (id, updated_at) VALUES (1, 0)`。

### 3.2 channels（短信通道）

| 列 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| id | TEXT | PRIMARY KEY | UUID |
| name | TEXT | NOT NULL | 通道名称（API 层校验非空） |
| description | TEXT | NOT NULL DEFAULT '' | 说明 |
| enabled | INTEGER | NOT NULL DEFAULT 1 | 启停（1/0） |
| config_json | TEXT | NOT NULL DEFAULT '{}' | 结构化通道配置 JSON（request/constants/body_mappings/sign/response/mobile_policy/receipt），密钥常量值不内联 |
| created_at | INTEGER | NOT NULL | 创建时间（毫秒） |
| updated_at | INTEGER | NOT NULL | 更新时间（毫秒） |

`config_json` 以「解析补默认值后再规范化序列化」的形态落库，字段语义见 [02 · 功能模块说明文档](./02-功能模块说明文档.md) 第 4 节与 [03 · API 接口文档](./03-API接口文档.md) 第 6.1 节。

### 3.3 channel_secrets（通道密钥密文）

| 列 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| channel_id | TEXT | NOT NULL，FK→channels(id) ON DELETE CASCADE | 所属通道 |
| name | TEXT | NOT NULL | 密钥常量名（如 appSecret） |
| ciphertext | TEXT | NOT NULL | AES-256-GCM 密文（base64(nonce‖ciphertext‖tag)） |
| updated_at | INTEGER | NOT NULL | 更新时间（毫秒） |

主键：`PRIMARY KEY (channel_id, name)`。密钥名必须已在 `channels.config_json` 的 constants 中声明 `secret=true`，否则 API 拒绝写入。

### 3.4 bindings（场景绑定）

| 列 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| sms_type | TEXT | PRIMARY KEY | 飞连 9 种场景之一 |
| channel_id | TEXT | NOT NULL，FK→channels(id) ON DELETE CASCADE | 目标通道 |
| template_code | TEXT | NOT NULL DEFAULT '' | 厂商模板码（API 层校验非空） |
| param_index | TEXT | NOT NULL DEFAULT '[]' | 参数下标序列 JSON 整数数组（如 `[2,1,0]`，`[]`=原序） |
| enabled | INTEGER | NOT NULL DEFAULT 1 | 绑定启停 |
| updated_at | INTEGER | NOT NULL | 更新时间（毫秒） |

保存为整批替换（单事务），API 层在写库前完成全部行校验，杜绝半成品批次。

### 3.5 sms_send（发送留痕与幂等状态机）

| 列 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| app_sms_id | TEXT | PRIMARY KEY | 我方幂等键（event_id / event_id-i / test-前缀） |
| event_id | TEXT | NOT NULL DEFAULT '' | 飞连事件 ID（测试发送为空） |
| source | TEXT | NOT NULL DEFAULT 'feilian' | `feilian` / `test` |
| channel_id | TEXT | NOT NULL DEFAULT '' | 使用的通道 |
| sms_type | TEXT | NOT NULL DEFAULT '' | 场景类型 |
| mobile_masked | TEXT | NOT NULL DEFAULT '' | 脱敏手机号（前 2 后 2 落库形态，如 13****56） |
| params_masked | TEXT | NOT NULL DEFAULT '[]' | 脱敏参数 JSON 数组 |
| template_code | TEXT | NOT NULL DEFAULT '' | 模板码 |
| status | TEXT | NOT NULL DEFAULT 'pending' | `pending`/`success`/`failed` |
| provider_msg_id | TEXT | NOT NULL DEFAULT '' | 厂商消息 ID（示例厂商 data.id） |
| provider_status | TEXT | NOT NULL DEFAULT '' | 厂商同步状态（HTTP 码或业务码文本） |
| provider_message | TEXT | NOT NULL DEFAULT '' | 厂商同步描述 |
| delivery_status | TEXT | NOT NULL DEFAULT '' | 回执送达态：`delivered`/`delivery_failed`（空=无回执） |
| delivery_message | TEXT | NOT NULL DEFAULT '' | 回执状态描述（示例厂商 statusMessage） |
| seq_no | INTEGER | NOT NULL DEFAULT 0 | 回执序号（示例厂商 seqNo） |
| receipt_at | INTEGER | NOT NULL DEFAULT 0 | 回执到达时间（毫秒） |
| error_kind | TEXT | NOT NULL DEFAULT '' | 失败分类（见第 8 节） |
| latency_ms | INTEGER | NOT NULL DEFAULT 0 | 下游调用耗时（毫秒） |
| created_at | INTEGER | NOT NULL | 记录创建时间（毫秒） |
| updated_at | INTEGER | NOT NULL | 最近状态变更时间（毫秒） |

索引：

| 索引 | 列 | 用途 |
|---|---|---|
| idx_sms_send_status_created | (status, created_at) | 待补发 pending 扫描、按状态+时间列表 |
| idx_sms_send_event | (event_id) | 按飞连事件追溯 |
| idx_sms_send_channel | (channel_id, created_at) | 按通道+时间列表 |

幂等写入使用「不存在才插入」（InsertPendingIfAbsent），配合状态终态判定保证重推不重发。

## 4. 状态机

```
pending ──同步成功判定──▶ success   （终态）
pending ──降级/渲染/网络/超时/业务失败──▶ failed（终态）
回执只更新 delivery_status/delivery_message/seq_no/receipt_at，不改变 status。
```
- `success`/`failed` 命中即跳过，不重复下发。
- 仅 `pending` 且 `now-created_at >= stale_pending_ms` 时允许续发一次（沿用原行），用于「已发送但回写前崩溃」的补偿；在途未超阈值的 pending 同样跳过。

## 5. 迁移与版本管理

- 使用 SQLite `PRAGMA user_version` 记录 schema 版本；启动时自动、幂等执行迁移。
- 每个版本在**单个事务**内执行全部 DDL/DML，成功后才写 `user_version`；任一步失败回滚并中止启动。
- 全部对象使用 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`，重复执行安全。

| 版本 | 内容 |
|---|---|
| v1 | system_settings（含占位行）、channels、channel_secrets、bindings |
| v2 | sms_send 与 3 个索引 |

新增表/列时在 `internal/store/migrate.go` 的 `migrations` 追加新版本即可；SQLite 兼容性约束下不使用窗口函数。

## 6. 配置快照与热生效

- 进程内维护不可变 `Snapshot{version, settings, channels(含解密密钥), bindings}`。
- 任一配置写事务提交后触发回调，从库全量重载并**整体替换**快照（读侧 RLock、替换侧 Lock）；请求路径每次读当前快照，O(1)、无锁竞争热点。
- 因此 Verification Token、webhook 路径、超时、通道配置与密钥、绑定改动均在「下一条请求」生效，不需要重启进程。

## 7. 密钥与敏感数据存储

### 7.1 主密钥（data key）
- AES-256-GCM 主密钥为 32 字节随机，来源优先环境变量 `SMSGW_SECRETS_DATA_KEY`（base64），否则密钥文件（默认与 DB 同目录 `data.key`，首启自动生成，0600/部署态 0640 root:sms-gateway）。
- 主密钥**不进数据库、不进 Git**；`.gitignore` 覆盖 `*.db*` 与 `data.key`。

### 7.2 通道密钥信封
- 算法：AES-256-GCM；每条密文随机 96bit nonce。
- 落库格式：`base64( nonce(12B) || ciphertext || gcm_tag(16B) )`，存于 `channel_secrets.ciphertext`。
- 解密失败（密钥不符、密文被篡改/损坏）显式报错；运行时解密明文仅存在于内存快照。

### 7.3 飞连 Encrypt Key
- 存于 `system_settings.feilian_encrypt_key`，经同一信封机制加密保护（空值=未启用）。API 仅回掩码与 `encrypt_key_set`，空提交不修改、`clear_encrypt_key` 显式清空。

### 7.4 留痕脱敏
- `sms_send.mobile_masked`：手机号前 2 后 2（落库形态，如 `13800000056 → 13****56`）。
- `sms_send.params_masked`：每个参数分别掩码后存 JSON 数组。
- 日志脱敏更严格（手机号前 3 后 2、params 整体 `[REDACTED]`），见 [02 · 功能模块说明文档](./02-功能模块说明文档.md) 第 12 节。

## 9. 备份、恢复与维护

**备份**（必须同时备份数据库与主密钥，二者分离存放）：
```bash
# 1) 一致性检查点后复制（WAL 回灌主库）
sqlite3 /var/lib/sms-gateway/sms.db "PRAGMA wal_checkpoint(TRUNCATE);"
cp /var/lib/sms-gateway/sms.db /backup/sms-$(date +%F).db
# 2) 单独安全备份主密钥（环境变量值或密钥文件），勿与数据库同放
install -m 600 /etc/sms-gateway/sms-gateway.env /backup/sms-gateway.env.secured
```
> 也可在停服窗口直接复制 `sms.db`/`sms.db-wal`/`sms.db-shm` 三个文件；在线备份推荐用 sqlite3 `.backup` 或先 checkpoint。

**恢复**：将 `sms.db` 放回数据目录、恢复内容一致的 `SMSGW_SECRETS_DATA_KEY`（或 data.key），确保属主 `sms-gateway:sms-gateway`、目录 0750，重启服务即可。主密钥丢失将导致历史通道密钥无法解密，需在 WebUI 重新录入。

**数据保留**：本期不内置自动清理/归档；`sms_send` 仅追加审计。如需控制体积，可在运维侧按 `created_at` 定期归档（建议先停写或在低峰执行，并先备份）。后续版本可增加保留期任务。

**完整性校验**：`PRAGMA integrity_check;`、`PRAGMA foreign_key_check;`。

## 10. 容量与性能

- 典型事件单批 1 条、逐条同步发送，SQLite 单机完全满足；写串行 + WAL 支撑管理面与事件面并发读。
- 主要写入量 = 每日短信条数 ×（1 次 pending + 1 次终态更新，回执再 +1）；读取热点走内存快照，不压库。
- 单库文件随 `sms_send` 线性增长，按第 9 节策略归档即可长期运行。
